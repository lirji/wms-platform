# 全模块代码规范审查

范围为正式 Maven reactor 的十个模块及 `wms-console`。依照 Claude 的 project-refactoring、backend-implementation 和开发规范，复用既有业务边界、数据库、异常与运行设施。以下是本次落实的变化及保留的约束；生产容量、真实设备和历史业务待办仍按原交付状态管理。

## 模块结果

| 模块 | 结构与实际优化 | 重点保留的规则 |
| --- | --- | --- |
| contract | 库存、分配、取消、调拨、TCC、序列选择和观察分包；补充契约构造边界说明 | DTO 字段、版本、十进制及事件身份不变 |
| runtime | 消息协议、Kafka、Inbox、Outbox、窗口、恢复、指标、工作器和持久化分包；消息大小预算归协议所有；可空投影时刻转换移入 DatabaseInstants | 数据库提交先于 Kafka 位点；租约/领取代际；重试、批量、缓存与健康预算不变 |
| security | 身份、中央授权协作簇、恢复 HTTP 分包；补充配置来源、异步结束和身份诊断说明 | Auth 权限判断、固定机器主体、企业/仓/成员代际校验与失败拒绝不变；不增加 ALLOW 缓存 |
| integration | WCS 模型、端口、错误与模拟器分包；状态使用稳定 code 的枚举；修复拒绝回执污染去重记录及竞争重放读取中间态 | 合法回执与 DTO 字段不变；模拟器仍只用于隔离测试 |
| inbound | 收货、质检、上架、任务和来源协议按实际入口/应用/持久化分包 | 本地事务、状态/版本、来源命令与上架身份不变 |
| outbound | 订单、授权、执行和来源协议细分；内部取消应用入口保持包内可见 | 拣发授权、未知结果、取消围栏、源命令幂等不变 |
| serial-registry | 主入口、配置、应用、领域、持久化和 HTTP 分包 | 企业 + SKU + SN 的身份、归属和调拨约束不变 |
| fulfillment | 订单协作簇、分配、调拨、TCC、观察、恢复、持久化与 HTTP 细分；纯错误工厂回归领域异常 | 私有协作边界、预留/取消/终态、事务及分支身份不变 |
| inventory | 主数据、库存、作业、盘点、序列、对账、快照、迁移、TCC 和调度职责细分；JDBC 应用服务退出 domain；历史序列凭证校验成为共享纯规则；摘要复用 RuntimeMessage.hash | 精确数量/FEFO/效期、桶与账本、Owner 仓、租约/CAS、跨仓归属、窗口证据不变 |
| test-support | 韧性场景、路由、上下文、调度与持久化分组；子进程入口引用同步 | 夹具所有权与私有协作保留，真实故障断言及必须运行的 profile 不删减 |
| console | 保留已有 features/shared/auth/shell；统一格式；修复上下文清空后的旧查询错误 | 真实接口、菜单/操作目录、授权范围、异步写入和原交互不变 |

原项目未提交的 `wms-execution-driver` 已只读核对，既有细分包且未引用本次迁移的内部全名；其源文件、pom、文档和工作状态仍归原任务所有，本次不交付其未发布功能。

## 开发规范落实

中文方法说明按实际职责补充：Mapper 说明 SQL 权威、行锁、唯一约束与影响行数；应用方法说明作用域、幂等、状态与恢复前提；契约说明构造边界；配置说明权威来源；生命周期与异步回调说明结束和资源归还。简单访问器说明字段用于何种身份或策略判断，保留已有中文类注释与复杂分支说明。用 JDK AST 检查正式后端主源码的显式公开方法及接口方法；构造器也包含在检查中，编译器生成的 record 访问器不机械增加包装。

SQL 仍在 Mapper/XML 或既有基础设施内。120 份迁移及 64 份 Mapper 的 SQL 文本单独核对，避免“编译通过但 SQL 丢失”的误判。本次没有建表、数据回填或新的数据写入权威。没有重新选择中间件、升级后端运行依赖、改变配置默认值、缓存一致性、资源预算或事件保留策略。

数据库转换与纯领域规则分离：`ExpiryPolicy.satisfied` 只接受瞬时；投影中的 null、Instant、Timestamp、Date 及墙钟拒绝规则由 `DatabaseInstants.instantOf` 保留。旧入口移除前已运行同一组特征测试，迁移后再运行。未扩大可接受时间类型，也未猜测时区。

封闭 WCS 状态采用显式协议 code，不使用 ordinal。合法请求与既有观测状态保持；无效回执应被拒绝且不得占用事件身份。先新增失败用例证明原缺陷，再实现校验先于去重写入；并发重放测试检查仅一次首次接受且全部看到完成状态。该修复不声明真实设备验收或生产吞吐。

控制台清空 token/查询上下文时同步清除旧错误、行和载荷；先保存原失败测试再验证修复。没有添加页面 Mock 或新的设计系统。

| 无效 WCS 回执及竞争重放 | CHANGED | 修复原错误副作用；合法回执、错误码集合与 DTO 不变 |
| 清空查询上下文后的旧错误 | CHANGED | 清除与当前上下文无关的错误显示 |
| 主应用与种子 CLI 入口、正式业务规则、预算与配置 | UNCHANGED | 不调整正在运行的制品 |

各批提交可正常反向提交回退；包移动及消费者引用需整批回退，不能只回退 Mapper 或启动注册文件。数据库和事件无迁移，本次无需数据补偿。代码合入 main 不等于运行制品已更新。

## 验证入口与限制

`scripts/check-module-packages.py` 检查正式 reactor 的源码目录、Mapper namespace 与资源路径、自动配置引用，以及纯领域对 JDBC/HTTP/缓存实现的依赖；真实集成测试继续证明 SQL 和事务语义。格式检查、脚本测试、全单测、默认 verify 和 warehouse/tc/failure profile 均沿用正式 CI。

实际执行结果与准确提交以 [重构报告](PROJECT_REFACTORING_REPORT.md) 和 CI 链接为准。原始失败、基线、AST 检查与技能卫生扫描保存在任务工作树的 `.local/refactoring-module-packages/`，不把私密构建/运行证据加入 Git。

历史大型应用服务和 Map 投影契约仍存在。此次明确模块和责任边界，不为追求类型数量改动公开 JSON，也不机械引入透传层。主 bundle 约 827 KB 的既有构建提示仍记录；生产容量、现场设备、OQ-03 和全部 50 项 AC 沿用原门禁，不能由本次重构测试替代。
