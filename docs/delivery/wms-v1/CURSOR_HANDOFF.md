## 2. 页面状态要求

- Loading 保留上下文且禁止重复提交；空态显示当前过滤条件和允许动作。
- 202 显示处理中及 operationId，轮询退避并可恢复；不能显示业务已成功。
- 409 版本冲突显示最新记录及需要重新确认的操作；不自动换幂等键。
- 权限不足隐藏不可执行动作并展示拒绝原因；服务端仍为最终权限权威。
- TCC TRIED等待恢复展示“库存已预留，等待Seata全局事务完成”，禁止提供任意强制释放按钮。
- serial待登记/待转移确认显示隔离状态，禁止拣货或发运。
- 查询显示asOf与延迟；陈旧时提示刷新/等待，按钮写入由服务端重校验。
- 部分发运/盘点调整显示已提交和未完成明细；取消只针对允许取消的剩余部分。
- PDA扫码区支持扫码枪连续输入、回车提交、键盘焦点恢复、声音与可视反馈；不能只靠颜色表达成功/失败。
- 离线仅暂存扫描意图，显示待同步数量、设备会话、冲突项；不伪装“库存已更新”。

## 4. 交付与验收

实施前端时改 `wms-console/` 和约定前端文档路径；接口不足时可直接补齐后端契约、迁移与实现，不必只反馈给其他工具。需提供分支、提交、锁文件、运行/构建/测试命令及关键页面状态证据。

UI验收按AC-26并覆盖AC-01/07/13/18/24/25用户路径：收货→上架→跨仓分配→拣货→部分发运→剩余取消回库；另测断网重连、重复点击、权限拒绝、版本冲突和对账差异修复。

验收状态依次为 prepared → implementation-pending → ready-for-verification → accepted；只有对返回实现做真实API联调和交互验证后才 accepted。前端构建通过不等于现场PDA/硬件验收。

## 5. v0.4三服务拆分交互要求

公开入口按资源路由到inbound/outbound/inventory；客户端不连接数据库或选择物理分片。收货/拣货/发运等库存同步返回202，页面同时展示physicalStatus与stockSyncStatus、commandId及结果查询入口；“货已发出、库存待同步”禁止再次发运按钮。重试库存同步沿用原命令，不能创建新设备动作。

新增AC-40：来源已记录事实、库存未过账；库存已过账、来源回执丢失；取消等待核验；冻结排空等待；设备UNKNOWN人工处理。每种状态提供原因/恢复进度，不能笼统显示失败后让用户重做。生成OpenAPI/前端类型时以v0.4结果契约为准。

## 6. v0.3 TCC交互

跨仓显示TCC_TRYING/TCC_COMPLETING/RECOVERY_PENDING及各仓进度；不能因一个仓Confirmed就显示整单分配成功。用户取消显示申请中，直到TC回滚完成或已提交后的业务取消收敛。TC不可达不显示“已释放”。无需用户理解XID，诊断详情供有权限运维查看。

## v0.4身份恢复与安全重授权

用户已批准补齐四项幂等协议。页面从任务恢复effectId/当前executionAttempt，网络重试保留clientOperationId和commandId；不得通过刷新页面或新随机键重做旧效果。分批收货/补拣通过服务端创建有额度的独立动作槽；“修改后重新授权”调用受控接口，只有服务端证据允许才显示可执行。UNKNOWN、STARTED或已发生实物事实时显示核验/恢复入口；APPLIED展示原结果与合法补偿入口。REJECTED历史结果不被新的安全关闭状态覆盖。契约见04第7节，验收对应AC-47..50。
