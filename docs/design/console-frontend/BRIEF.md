# 控制台前端重设计 — 框定

## 问题与角色

自营仓作业人员需要在一个浏览器应用里完成收发存、跨仓履约、盘点与对账。库存与单据权威在后端服务，页面只展示和提交命令。

| 角色 | 主作业 |
| --- | --- |
| 仓主管 / 内勤 | 选仓、看待办与陈旧查询、打开各作业台 |
| 收货员 | 入库单、收货扫描、质检、上架 |
| 库存 / 资料员 | 主数据只读、余额与 asOf |
| 履约 / 出库员 | 全局单与仓子单进度、拣包装发 |
| 调拨 / 盘点员 | 发出接收、冻结点数调整 |
| PDA 操作员 | 同一应用的扫码收货页，不是第二套原生 App |
| 对账 / 运维 | cutoff 差异与任务异常，不要求用户理解 XID |

## 用户可见主作业

1. 统一身份登录后进入当前仓工作台
2. 只读主数据（SKU / 库位）
3. 入库、库存台账、出库履约、调拨、盘点、任务、对账
4. PDA 收货：扫码枪连续输入、回车提交、文字+声音反馈
5. 数量按字符串展示；202 只表示已受理

## 非目标

- 不在页面写死仓库、SKU 或库存表
- 不新造后端 JSON；只消费已发布 OpenAPI `/api/wms/v1`
- 不拆微前端或第二套移动工程
- 不做原生离线库存写；离线只允许显示待同步意图
- 不把 simulator 当真实设备，不发明 OQ-03
- 不改生产部署

## 约束（仓库已有，不是方法）

- 可运行进程仍是 `wms-console`（Vite + React + TypeScript + `oidc-client-ts`）
- 入口经 nginx / Vite 反代到 inbound / outbound / inventory / fulfillment
- 身份：`VITE_OIDC_ISSUER` 为空则停在配置态；有 issuer 无令牌则登录
- 交接：`docs/delivery/wms-v1/CURSOR_HANDOFF.md`（桌面工作台 + 同应用 PDA 页）
- 契约：`wms-contract/.../openapi/wms-v1.yaml`
