# 盘点完整身份观察

当前已通过定向验证，准备提交。盘点观察入口新增可选serialObservation，结构为schemaVersion=1及完整serialIds集合；允许0至200条。空集合明确表示全部未见，未提供字段仍表示数量观察。现有序列SKU即使当前没有本地身份也拒绝只录数量；普通SKU拒绝序列观察。

## 原输入与重放

V039追加count_observation.observation_kind和serial_input_json；完整规范化输入与原观察子行、最新点数及计划状态在同一事务提交。序列号去空格、统一大写、排序且拒绝重复，数量必须等于身份数。没有改写原迁移或回填未知历史观察。

同一观察编号固定企业仓、计划、行、数量、轮次、原操作人、观察类型及完整实见集合，不能等量换另一组SN，也不能将身份观察降为数量观察。原观察可在后续审批/调整/完成后重放，只读取原观察子行的FOUND/MISSING结果，不依赖已经变化的本地身份。较新轮次的最新点数不会因旧编号重放回退；新增编号的轮次必须递增。

旧序列观察没有完整输入证明时拒绝推测回填；旧数量观察保留同参数查询式重放。观察插入不再用INSERT IGNORE吞掉CHECK或截断错误，最后子行失败应回滚完整输入和当前点数。

## 预算与接口

单次完整输入最多200个实见身份，本地身份查询最多201个，发现原桶超过200时明确报COUNT_SERIAL_BATCH_LIMIT，不截断或伪报全部盘完。当前不支持单个大桶多段观察后合并的协议，应作为后续扩展范围，不能简单拆成多个独立完整观察。旧HTTP请求没有新字段时继续走数量观察；本次修正OpenAPI的观察成功响应为实际200。
