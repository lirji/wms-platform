# 序列号调拨源仓释放恢复

当前切片已通过定向验证，准备正常发布。源仓SEALED、数量扣减、TRANSFER_ISSUE流水与V038 serial_release_intent在同一本地事务提交。恢复只读取不可变的原企业仓、SKU、序列号、transferId、fromEpoch、releaseRef，不再次扣减，不从目的仓或后续ownerEpoch重建原事实。旧SEALED记录缺少意图时拒绝推测回填。先锁源库位门禁，再锁身份/余额并核对原桶，冻结期间不能调拨扣减；已有桶占用时不能猜测该SN尚未被预占。

## 传播与恢复

SerialReleaseRecoveryService每次至多20条，10秒内停止领取；每次实际HTTP另有1500ms截止。每条自动最多12次，指数退避带抖动、15秒领取租约及单调claim_epoch；最终失败隔离。网络调用不持有本地会话，迟到执行器通过领取代际条件更新被拒绝。迁移路由停写期间不领取、不完成、不人工重排。

既有serialTransferRecovery分别为源释放和收货/目的授权保留10秒领取预算，每类至多20条，单类积压不会耗尽另一类预算。20秒是停止新领取预算，不是包含数据库等待和最后在途HTTP的硬总耗时承诺。未配置真实受控服务凭据仍拒绝执行，不在运行时伪造登记成功。

## 历史事实与当前归属

新客户端携带X-Wms-Serial-Release-Proof: 1时，登记source-releases响应在原当前身份响应上新增sourceRelease凭证，包含企业、原SKU/序列号、源仓、原转移、释放引用和fromEpoch。原转移已有相同释放事实时允许跨后续转移重放，只返回历史凭证和当前身份，不修改当前归属。HTTP客户端及恢复器都核对完整原凭证，不用当前ACTIVE或ownerWarehouseId推断释放成功。

已有SerialCommandService每次重放重新检查领域状态，不读取旧缓存响应作为授权；此规则继续保留。新源恢复客户端遇到旧登记版本缺少sourceRelease时维持待重试/隔离，先升级登记、再升级库存执行器。未带协商头的旧来源客户端仍收到原字段集合；未知凭证版本返回400。同业务命令可以切换表示，不重新释放。

## 运维与迁移

serial-recoveries列表增加kind=SOURCE_RELEASE，operationId为原releaseRef；两张独立意图表按相同企业仓/状态过滤，分别有界查询后稳定合并分页。原恢复权限、JWT仓范围、审计命令及重排接口复用，重排仅重新授予预算并递增领取代际，不修改原事实。V038加入仓迁移清单，共50表；历史事实与未完恢复状态必须一起复制。原生RM迁移仍受TC证据门禁约束。
