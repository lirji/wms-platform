## 事务划分

公开applications先在短本地事务固定原输入；需要登记时返回202、status=REGISTRY_PENDING，库存和身份仍未调整。逐身份恢复器先提交领取，再释放数据库连接调用真实登记。MISSING使用原本地epoch和调整操作；FOUND认领/激活使用同一原操作。成功响应须匹配序列号、仓、原操作和终态；已有MISSING本地记录的盘盈需要更高epoch，全新本地盘盈接受实际登记epoch，不能固定写0。

每个身份结果单独持久化。回执丢失只重试该身份原操作，其他DONE身份不重发。全部结果齐备才将行意图推进READY；CountApplyRecovery只领取READY序列行，正常等待登记不消耗整行8次失败预算。数量、FOUND/MISSING本地变更、原流水、行终态与意图APPLIED在同一本地事务提交；最后写失败保留此前DONE远程结果以供重试。

本地应用只通过SavedResults读取已保存凭证，不调用网络。包括PRESENT在内的原实物身份必须先完成收货或转移登记，才固化调整快照；等待不消耗行预算，不猜测待授权身份的epoch。随后不允许改变原桶、SKU/批次、操作、状态和归属代际；在途登记后原实物身份集合或数量改变时拒绝应用旧结果。盘盈写实际epoch与新的receipt_operation_id；旧转移当前指针从新生命周期中移除，旧完整快照保留在不可变调整上下文，历史释放/转移意图不删除。

## 预算与恢复

每次至多准备20行、处理20个身份，20秒后停止新领取；每个实际HTTP仍受既有1500ms调用截止及租户配额约束。每个身份最多12次自动尝试、15秒租约和单调领取代际，失败退避/隔离。准备阶段等待原收货登记不消耗行失败次数，其他前置失败使用既有行预算；下次尝试时刻避免前20个失败行永久挡住后续行。

原有serial-recoveries列表加入COUNT_FOUND/COUNT_MISSING，沿用企业仓权限、原命令审计和代际重排。只有未应用的PENDING父意图下隔离身份可以重排，不修改原业务输入。旧CountService带登记端口的同步构造仍供既有内存测试使用，正式HTTP/作业通过新的持久结果路径；不能把旧同步测试当作真实网络事务证据。

登记HTTP对原MISSING命令返回同事务保存的历史盘亏确认，即使随后已盘盈也不丢失该事实。该凭证不授予持有权；CLAIM/ACTIVATE等仍验证实时状态，不能返回旧ACTIVE授权。查询接口仍返回当前身份。
