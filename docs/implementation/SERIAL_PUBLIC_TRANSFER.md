# 公开序列调拨

唯一验收为[剩余整改有限验收](../delivery/wms-v1/DELIVERY_PLAN.md)的TRANSFER。复用现有调拨单、库存序列恢复、登记HTTP和Kafka Inbox/Outbox，不增加中间件或退货业务。

## 数据所有权和顺序

- 履约库负责原调拨单/行、分批源发出与目的收货命令、选择的SN及原epoch、额度和业务完成状态。公开请求固定身份后返回处理中，重放不可换桶、换SN、换目的仓。
- 库存负责本仓数量、逐身份可用性与流水。源仓本地封闭和扣减、不可变准备/释放意图同事务；先封闭本地授权再由后台准备登记和传播释放，期间不能重复拣货。目的先持久HOLD与恢复意图，只有原登记确认才授权。
- 登记服务负责全局归属和epoch。准备/释放/目的接收使用原企业、SKU、SN、转移、仓、引用与epoch；HTTP未知结果复用原命令，不能生成新准备引用。
- 消息只传请求与核验后的回执；履约不写库存库，库存不改调拨单。复用既有消息隔离/重排；旧消费者遇到新增事件保持隔离，不静默忽略身份扩展。开启公开路径前部署完整消费者和登记能力。

## 有限实现顺序

1. 源封闭持久保存目的仓，恢复任务执行准备再释放，准备回执丢失不重复扣量。V046仅扩展nullable目的仓，旧意图继续原释放协议，禁止猜测回填。
2. 固定公开单据的原数量和SN命令，经现有消息路径交给库存；库存业务效果与原命令同事务。源释放/目的授权完成后可靠回执，履约才累计实际issued/received；处理中不伪报完成。
3. 公开查询/权限/重复与冲突、真实登记HTTP、原数量与身份一致、重启及非空迁移验收。审计重排复用既有登记和消息队列控制。

公开源发出、目的分批收货和原命令查询已实现。真实三服务进程验收通过，非空迁移组合检查通过；后续TC/COMP/FINAL不因此自动完成。
