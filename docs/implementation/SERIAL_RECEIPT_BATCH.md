# 按收货批次固化序列号观察

本切片已通过定向验证。批次始终使用来源RECEIVE commandId；一个序列号表示一个基本单位。公开收货请求可带`serialObservation: {schemaVersion: 1, serialIds: [...]}`，完整清单1至200条，去首尾空白并按ROOT大写规范化后排序，重复身份拒绝，数量必须等于清单长度。

## 来源与库存原子边界

来源T1从原单据取得货主、SKU和单位，将规范清单、库存上下文、原操作者与来源命令/Outbox一起提交。同收货事实换命令键仍返回原命令；省略、追加或替换原身份清单返回冲突。设备观察重放同样经过原来源上下文比较，不能借新请求篡改观察身份。

库存依据本库主数据判断序列号策略。普通SKU携带序列号观察被拒绝；序列号SKU缺失、超界、重复、版本错误或数量不符时不能入账。V037的`serial_receipt_batch`保存原清单及完整库存上下文摘要，与库存命令、一次聚合数量入账、全部local_serial、逐身份serial_recovery_intent和结果Outbox在同一库存事务中提交。任一身份冲突或最后写入失败整批回滚，不产生部分成功。

批次入口调用只绑定已过账身份的内部方法，不复用会额外增加数量的`stageHold`。旧已存在库存命令但没有批次清单时不能猜测补填。其他入口的已存在local_serial，即使操作ID碰巧相同，也不能由新批次接管。后续移动过的批次重放只核对原清单及命令，不把身份拉回原HOLD桶。

## 登记与后续范围

收货结果APPLIED证明本仓数量与身份意图已落地，不等于全局登记已授权。身份保持HOLD_RECEIVED，既有有界恢复执行器在事务外访问真实登记端口，授权后才将本地身份改为AUTHORIZED；质量仍为HOLD。登记不可用不回滚已收货实物，也不把它当作可预占GOOD库存。

后续[身份质检切片](SERIAL_RECEIPT_QUALITY.md)已接通QUALITY。PUTAWAY/PICK/SHIP序列号消息仍明确拒绝，待加入每一步明确的身份规则及登记授权校验；不能按累计数量猜测哪些序列号已经上架或发运。本切片不完成逐身份盘点、转移来源释放、正常发运登记终态或可信水位。

## 兼容与迁移

没有新增依赖或中间件。旧普通SKU收货请求继续省略观察字段；旧序列号消息保持拒绝，不能自动补齐。先部署具备V037及新消费者的库存服务，再启用发送观察的来源版本；旧消费者会拒绝序列号消息，需要原消息审计重放，不能宣称混合版本自动放行。配置/来源回退前必须停止新序列号请求并处理待发事件，保留已产生的批次事实。

仓迁移复制允许清单同步包含serial_receipt_batch，当前49表；本切片不解除原生RM仓迁移终态门禁，不执行共享或生产迁移，不删除历史观察。
