# 仓迁移实现与边界

`WarehouseMigrationStore` 在 `main 3e2c720` 显式维护52张含企业/仓范围的表，包括盘点、消息接收/恢复、对账/快照、归档候选、序列号恢复及原生RM登记意图；包含源释放、盘点调整与逐SN盘点意图。真实数据库元数据测试会检查所有同时含enterprise_id和warehouse_id的表都进入清单；warehouse_route是单独控制的路由状态，不能作为普通业务表覆盖目标。

数据库时间规则是物理库属性，不随仓复制。源目标必须已登记storage_offset，连接会话与登记值一致，两库偏移相同；跨偏移会改变原始归档行摘要，本实现明确拒绝，不能当作普通搬迁自动转换。企业共享SKU/单位/货主等目录、TC的无仓Fence表也不因仓过滤自动复制；目标环境必须按其数据所有权准备这些依赖。

目标仓必须是同一源/目标配对的COPYING状态，每批在目标事务内锁定路由并检查。ACTIVE或其他迁移占用的目标拒绝覆盖。每批最多200行；表/列来自固定允许列表与受校验元数据，值绑定。复制后逐行比较完整值，目标其他企业/仓同主键、其他唯一键碰撞或不可变审计/流水内容冲突都会回滚当前批次，不用INSERT IGNORE吞掉错误。先前已提交的复制批次保留在COPYING目标中，尚不代表整个迁移成功。

停写不能覆盖已有盘点冻结或其他维护门禁；迁移仅将OPEN改为自身的MAINTENANCE，回退/激活仅开放原因是WAREHOUSE_MIGRATION的门禁。新切流要求源仓QUIESCING且通过表计数和库存数量校验；此校验不是全表业务语义或全局分布式一致性证明。

两库提交不原子。目标已激活而源提交失败后，只允许相同源/目标/epoch的精确重放完成源库收尾，不再覆盖目标数据，不重新开放目标随后产生的冻结门禁；不同epoch或其他迁移不视为成功。目标已接受写入后不能直接切回旧库。

仍未完成的整体运行门禁：真实TM/RM回调路由、在途TCC与Fence/终态证据迁移、所有来源/后台写入排空和目标共享目录准备，继续随R13/R14接线验证。当前测试是隔离MySQL之间的复制/故障验证，未执行生产迁移、共享库覆盖或灾备承诺验收。

原生RM意图存在的仓暂时拒绝迁移停写，须先完成TC终态通知和资源/Fence迁移验证；本地二阶段结果不能证明TC已收到回执。详见[原生RM运行边界](RUNTIME_TCC_RM.md)。
