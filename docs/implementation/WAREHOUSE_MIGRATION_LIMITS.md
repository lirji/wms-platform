# 仓迁移实现与边界

`WarehouseMigrationStore` 显式维护58张含企业/仓范围的表，包括盘点、消息接收/恢复、对账/快照、归档候选、序列号恢复及原生RM登记意图；包含源释放、盘点调整、逐SN盘点意图、原拣货身份与发运意图。真实数据库元数据测试会检查所有同时含enterprise_id和warehouse_id的表都进入清单；warehouse_route是单独控制的路由状态，不能作为普通业务表覆盖目标。

数据库时间规则是物理库属性，不随仓复制。源目标必须已登记storage_offset，连接会话与登记值一致，两库偏移相同；跨偏移会改变原始归档行摘要，本实现明确拒绝，不能当作普通搬迁自动转换。企业共享SKU/单位/货主等目录不随仓过滤自动复制，目标环境须按数据所有权准备。TC的无仓Fence表通过原RM意图与终态证据精确定位、单独复制及逐字段核验，不搬迁其他仓的Fence。

目标仓必须是同一源/目标配对的COPYING状态，每批在目标事务内锁定路由并检查。ACTIVE或其他迁移占用的目标拒绝覆盖。每批最多200行；表/列来自固定允许列表与受校验元数据，值绑定。复制后逐行比较完整值，目标其他企业/仓同主键、其他唯一键碰撞或不可变审计/流水内容冲突都会回滚当前批次，不用INSERT IGNORE吞掉错误。先前已提交的复制批次保留在COPYING目标中，尚不代表整个迁移成功。

停写不能覆盖已有盘点冻结或其他维护门禁；迁移仅将OPEN改为自身的MAINTENANCE，回退/激活仅开放原因是WAREHOUSE_MIGRATION的门禁。新切流要求源仓QUIESCING且通过表计数和库存数量校验；此校验不是全表业务语义或全局分布式一致性证明。

两库提交不原子。目标已激活而源提交失败后，只允许相同源/目标/epoch的精确重放完成源库收尾，不再覆盖目标数据，不重新开放目标随后产生的冻结门禁；不同epoch或其他迁移不视为成功。目标已接受写入后不能直接切回旧库。

TC终态通知、原资源/XID/branch/Fence和实际迁移重启验证见[TC资源迁移](TC_RESOURCE_MIGRATION.md)。源仓全部原生RM意图必须具有匹配TC终态、本地回调与Fence；历史预占缺原RM来源时保持阻断，不猜测回填或删除绕过。目标恢复原应用/资源别名后，真实TC重复回调只读返回原终态。

生产迁移仍须排空所有来源与后台写入、准备目标共享目录、更新明确的消息路由清单并完成运维验收。这里未执行生产迁移、共享库覆盖或灾备承诺验收；不能用隔离测试替代这些环境条件。
