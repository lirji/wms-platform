# 收货批次的序列号分次上架

本切片已通过定向验证。上架请求新增可选`serialSelection: {schemaVersion: 1, serialIds: [...]}`，明确本次选择的1至200个身份；数量必须等于规范化后唯一身份数。完整收货清单与本次选择分开，支持同一收货批次分次上架。普通SKU原请求继续兼容。

## 来源受理

来源T1先从原收货命令确认全部所选身份属于本批，再从当前已经APPLIED的质量命令读取具体合格名单。V016新增inbound_serial_putaway，唯一键为企业、仓、原收货命令和规范序列号；同一身份只能绑定首次上架任务及命令，不能因另一个任务的总数量仍合法就重复领取。

身份占用、来源实物数量、任务、来源命令及Outbox在同一事务提交。最后任务写失败不会留下身份占用。重放先比较原命令上下文与所选清单，不用当前余额重新解释原任务；更换名单或遗漏名单冲突。库存回执未知时保留原任务和占用，不释放后重新创建动作。

质检后续版本也检查已受理上架的具体身份仍在合格集合，包含“合格总数不变但替换序列号”的情况。此表只管理来源任务受理，不成为全局序列号归属权威。

## 库存落地

库存基于本库主数据判定序列号策略，再核对本库原收货清单、原receipt_operation_id、企业仓/SKU/批次、当前源桶和AUTHORIZED/ACTIVE登记状态。所选身份已经移出、属于其他批次或进入转移时拒绝。源桶存在reserved/free_execution_claim时不猜测哪些身份仍可自由上架。

本批合格额度、数量移动、全部所选local_serial.balance_id、完整身份凭证、库存命令和结果Outbox在一个库存事务内提交。最后身份写失败全部回滚。所选清单参与命令摘要，旧命令重放只返回原凭证，不把后来已移动的身份拉回去。
